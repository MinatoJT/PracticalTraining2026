# 配置、变更与质量记录约定

文档编号：PT2026-CM；版本 0.1；状态：建议工作约定，待维护者采用。这里定义下一步如何留证，不声称小组已执行全部流程。

## 1. 配置项及基线

| 配置项 | 标识与控制要点 |
|---|---|
| 源码与文档 | Git 提交 SHA；本轮分析基准 `870ec0ae954e1035ba34ab30f90e07b1cf158496` |
| 依赖 | 工程 requirements、Python/OS/硬件及实装版本；当前未形成锁定环境 |
| 模型与服务 | 模型 ID、端点、超时、调用日期；密钥只留凭据引用，不入版本库 |
| 检索与数据 | 数据集名称/revision、索引版本、分割、样本 ID/顺序、随机种子 |
| 实验参数 | task/agent、阈值、Web/历史/稳定知识开关、judge 口径 |
| 运行证据 | 完整日志、逐轮结果、汇总、trace、缺陷与复测记录 |
| 历史快照 | 保留 `agents/`、`Legacy失败/` 和旧笔记；不得静默覆盖为新结果 |

代码基线、数据基线、环境基线和实验结果要一起标识。提交存在不代表发布，文档版本 0.1 不代表软件版本或验收通过。

## 2. 轻量变更流程

1. 在任务记录或 PR 说明问题/目标，关联 REQ 与 VAL；列出影响的接口、数据、成本和风险。
2. 独立分支实施，避免把文档整理与无关算法改动混在一起；保留历史文档。
3. 检查源码与说明是否一致，执行受影响用例；明确通过、失败、阻塞、未执行。
4. 请维护者评审设计/需求影响、测试证据和未解决风险；保存意见与处理结果。
5. 仅获批准后合入/发布；登记最终 SHA、配置与证据位置，必要时重新运行关联测试。
6. 发现回归时定位引入提交，选择可恢复版本；回滚环境与数据兼容性也需复核。

角色按实际小组安排填写：变更责任人、评审人、测试执行人和验收人尚未指定，不能代填签名或批准日期。
